A collaborative operating system for people and AI agents

A complete Linux desktop running inside a container with no physical monitor, streamed to the browser over WebRTC — and driven, at the same time, by people and by an agent that sees and acts on the same screen. Same X display, same session, same room.

The idea

Two independent control planes over one desktop

The second half is not a metaphor for an API. A person drives through a control layer in the browser; an agent drives through a local Unix socket. Neither is a guest of the other, and that separation is the single most important thing about the design.

People, over WebSocket

/ws is the only door. The first frame must be an authentication frame; until it validates there is no SDP offer, no ICE and no DataChannel. Keyboard and mouse arrive on a data channel and go into X through XTEST.

Agents, over a local socket

A 0600 Unix socket exposes 114 tools to any MCP-capable host. The bridge is a thin stdio pipe spawned with docker exec, so killing the host never takes the desktop down with it.

Architecture

One capture, many observers

The screen is encoded once and fanned out: to every browser, to the recorder, to a live stream. A second participant costs bandwidth, not CPU. GStreamer runs inside the Go process, so every RTP packet goes from appsink straight onto the WebRTC track and the encoder stays reachable at runtime.

The encoder is picked at startup by running a real probe pipeline for each candidate — NVENC, VA-API, x264, then software VP8 — so the choice reflects what actually works on the host rather than what the drivers claim.

What it does

A real desktop, not a screenshot service

They take turns

Exactly one participant holds control. While a person is connected the agent has to ask, and a prompt appears on that person's screen with a timer; no answer means no.

Adaptive by design

Congestion estimation over TWCC steers the bitrate, a lost reference frame is answered with an immediate keyframe, and the shared encoder follows the slowest link so the worst connection is never dropped.

Structure, not pixels

An agent reads the screen as an accessibility tree or drives the real DOM through DevTools, so it clicks a button by name instead of guessing at coordinates.

Audio both ways

The desktop's sound reaches the browser, and the browser's microphone comes back as an ordinary capture device inside the desktop — a real input, not a monitor a page will refuse to list.

Files, clipboard, gamepad

A two-pane manager with Midnight Commander keys, drag-and-drop onto the page, a two-way clipboard, and a browser gamepad that appears inside as a virtual Xbox 360 pad.

Record and stream out

Record to MP4, WebM or MKV, or send the live session to YouTube, Twitch or your own VLC — reusing the encode the room is already producing rather than capturing twice.

Quick start

One command on a machine of its own

The installer downloads one binary and asks it for everything else: the binary embeds its own deployment files, so configuration and code can never disagree about versions. auto picks Docker when it is present and a native systemd install otherwise.

Full installation guide 
# VPS or Raspberry Pi 5 (Debian 13 / Raspberry Pi OS)
curl -fsSL https://raw.githubusercontent.com/\
lordbasex/sentineldesk/main/install.sh | sudo bash -s auto

# or, from a clone, for development
make up   # → http://localhost:8080

Set AUTH_USER and AUTH_PASS before exposing it. Without them authentication is disabled, which is for LAN development only.
